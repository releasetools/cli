# Modules

## Contributing new modules

A few conventions can be found below:

- each file must have the `.bash` extension
- each file must start with `#!/usr/bin/env bash`
- each file represents a namespace that should be called accordingly (e.g., `foo.bash` should define the `foo::*` namespace)
- each file should have one `[namespace]::_internal_check_deps()` function that checks if all required dependencies in that module are available at runtime
- namespaces and functions that start with `_` are private, meaning they are left out of the listing printed by the executor script. They are still reachable if you name one explicitly, so treat the underscore as a convention rather than a boundary
- define only `[namespace]::*` functions. A bare function name shadows any binary of the same name for everyone who sources the library, so a `helm()` in a module would make the real `helm` unreachable
- `base::check_deps()` is a reserved name and is automatically generated by [scripts/generate-dist.sh](../scripts/generate-dist.sh); it will run `[namespace]::_internal_check_deps()` for each defined namespace and is meant to be used for confirming that any function defined in the `releasetools` library will function correctly

## Writing functions

- return, never exit. The distributable is sourced as well as executed ([scripts/install.sh](../scripts/install.sh) sources it), and an `exit` from a library function kills the caller's shell with no way to intercept it
- keep stdout for the return value and send everything else to stderr. Callers capture stdout with `$(...)`
- a failing command inside `$(...)` does not trigger `set -e` in the calling shell, so check the exit status explicitly rather than assuming a failure propagates. `if ! value="$(...)"; then` is the usual shape

## Shell support

The library requires **bash**. It is not zsh compatible, and no attempt should be made to make it so, because the cost lands on every module rather than in one place.

`scripts/main.sh` enables `set -euo pipefail` at the top level of the concatenated file, so sourcing the distributable turns those on in the caller's shell too.

Sourcing it from zsh will get you a long way, since most functions are portable, and that is exactly the problem: the ones that are not tend to return a plausible wrong answer instead of failing. `base::install_location` is the example that prompted writing this down. It resolves the install directory from `BASH_SOURCE`, and zsh sets `$0` to the running function's name inside a function body, so it used to print the caller's current directory with a success code. It now refuses.
